# v0.3.0 数据备份、升级与回滚（给使用者）

> 这份文档是**操作说明**，不是工程验证报告。工程侧的证据在
> `docs/v0.3.0-upgrade-verification.md` 与 `test/v0300-*.test.ts`。
>
> 一句话原则：**升级前先复制一份数据目录。** 三分钟的复制，换掉一次不可逆的风险。

---

## 一、你的数据在哪

| 数据 | 位置 | 里面有什么 |
| --- | --- | --- |
| 会话与候选 | `<storeDir>/state.json` | 导入过的讨论、候选回复、人工批准、安全事件、去重记录 |
| 出网审计 | `<storeDir>/egress.jsonl` | 每一次外发请求的记录（谁发起、去哪、被允许还是拒绝） |
| 插件配置 | DSH profile 的 `cordis.patch.yml` | 人格、强度、模型来源、字数上限等 |
| 模型凭据 | 宿主 keyring 或环境变量 | **不在上述任何文件里**，插件从不落盘密钥 |

`storeDir` 的默认位置因安装方式而异。在插件设置页的「数据目录」一行能看到**实际生效的
路径** —— 请以那里显示的为准，不要按本文档猜。

---

## 二、备份（升级前必做）

1. 完全退出 DSH Desktop（不是关窗口，是退出进程）；
2. 把上表里的 `storeDir` **整个目录**复制到另一个位置，例如
   `D:\dsh-backup\2026-11-09\`；
3. 顺便复制一份 `cordis.patch.yml`；
4. 记下当前版本号（设置页或 `package.json` 里的 `version`）。

**为什么要退出进程**：写盘是「先写临时文件再改名」的，进程运行中复制可能拿到中间态。
退出后复制，拿到的就是一份完整一致的文件。

**备份里不该有什么**：如果你在备份目录里看到 `Cookie`、`apiKey`、`token` 之类的文件，
说明那不是插件的 store —— 插件不写这些，遇到请当异常处理，不要把它上传到任何地方。

---

## 三、升级

1. 退出 Desktop；
2. 备份（上一节）；
3. 按安装方式升级到新版本（`dsh plugin add <新的 tgz 或仓库引用>`）；
4. 启动，打开插件页，确认能读到旧会话；
5. 打开其中一条旧会话，确认步骤与候选还在。

**升级后会发生什么**

- 旧会话按原 `id` 读得到，标题、状态、候选数不变；
- 旧候选的 `approved` 布尔值**仍然读得出来**，但它**不构成一次发表授权** ——
  发表路径要的是批准记录（绑定正文哈希、目标快照、账号），旧版本没有这种记录；
- 新生成的候选一律 `approved: false`，不会继承任何旧批准。

---

## 四、回滚

如果升级后出现问题：

1. 退出 Desktop；
2. 把旧版本装回去；
3. 把备份的 `storeDir` 目录**换回来**（先改名当前目录，再放入备份，别直接覆盖 ——
   覆盖到一半失败会同时丢两份）；
4. 启动，确认会话还在。

**回滚不会丢失**：备份里已有的会话与候选。
**回滚会丢失**：升级之后新产生的会话与候选 —— 它们不在旧备份里。所以「升级后先看能不能
用，再决定要不要继续用」比「用一周之后再想回滚」安全得多。

---

## 五、损坏了怎么办

| 现象 | 插件的反应 | 你要做的 |
| --- | --- | --- |
| `state.json` 整份损坏（截断、乱码） | 拒绝启动并说明原因，**不覆盖**原文件，留在旁边 `*.corrupt-*` | 用备份换回；或把坏文件留着，从备份恢复后对比 |
| 只有一个会话的字段坏了 | 要么整份拒绝并说明，要么读得出好的那些 —— 不会「少了东西还不吭声」 | 看提示里的字段名，从备份取回那一条 |
| 上次写到一半留下 `state.json.tmp` | 忽略它，正常启动 | 不用管，可在退出后删除 |
| 配置里有坏值 | 落回默认值（人格不认识的落默认人格、非数字落默认数字） | 在设置页重新选一次 |
| 提示「版本不认识」 | 拒绝启动，不静默降级 | 说明这份数据来自更新的版本；装回新版，或从备份恢复 |

---

## 六、这些事插件不会做

- 不会在升级时自动清理旧会话；
- 不会把旧批准变成新授权；
- 不会因为某个字段读不出来就静默删掉整份数据；
- 不会把模型密钥写进 `state.json`；
- 不会在你没点「批准」的情况下让任何候选变成可复制状态。

---

## 七、仍然需要人工判断的一件事

**备份策略是你自己的决定。** 插件不会自动帮你备份，也不会提醒你备份 ——
一个会自己动你数据的备份功能，风险比没有更大。
