# v0.3.0 外部评审材料（真实人员使用）

> **这份材料是给真实的人用的，不是给自动评审冒充的。**
> 如果没有人真的读、真的用，对应项目就记录为「未完成」，不得填分。

---

## 一、给测试者的一页说明

你要做的只有一件事：从零装好，用它写一条你能接受的回复。

1. 安装 v0.3.0 候选包（`dsh-ai-debate-0.3.0.tgz`）。
2. 配好模型（宿主模型或你自己的 OpenAI 兼容接口）。
3. 粘一段你熟悉的讨论，选一个你想回的人，生成一条回复。
4. 改到你满意，批准，复制出来。
5. 填写下面的反馈表。

**请记录你卡住的每一步**，包括「看不懂按钮」「不知道下一步点哪」「提示看不懂」。
这些比「整体感觉不错」有用得多。

**不要提供**：API Key、Cookie、真实账号、未脱敏的聊天记录。

---

## 二、匿名人工评分表（30 条）

评分对象：两条回复（A / B）来自不同构建，顺序打乱、不告诉你是哪一版。
每条 1–5 分（1 = 明显不行，3 = 及格，5 = 很好），拿不准就写「不确定」。

评价维度：

| 维度 | 问题 |
| --- | --- |
| 目标 | 它回的是你选的那个人吗？ |
| 事实 | 有没有编造原文里没有的事实或数字？ |
| 引文 | 引用的内容能在原文里找到吗？ |
| 针对性 | 它回应了对方的核心论据，还是只说空话？ |
| 上下文 | 有没有漏掉关键前提、把不同时间的话混在一起？ |
| 自然度 | 像人说的话吗？ |
| 人格 | 符合所选人格吗？ |
| 策略 | 打法与材料匹配吗？ |
| 材料不足 | 该追问时追问了吗？该写时写了吗？ |
| 攻击性 | 有没有不必要的人身攻击？ |

## 四、组织者必须遵守的边界

1. **不代替测试者填表。** 没做就是没做。
2. **不把自动评审写成人评。** 自动规则可以整理、分类、排序，不能给「人觉得好」的结论。
3. **不泄露测试者信息。** 姓名、账号、聊天原文都不进仓库。
4. **发现严重问题先修再复评。** 修完要对**同一批固定案例**重跑，不能换一批更容易的。
5. **未达到人数/完成率时，正式 Beta 的用户验收标记为未通过。** 代码与 RC 可以保留，
   发布报告必须写明阻断原因。
