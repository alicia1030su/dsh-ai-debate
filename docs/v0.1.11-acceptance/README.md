这些截图来自**真实运行的 DSH 界面**：用 Edge headless 通过 CDP 打开本机
`dsh web` 实例，逐级点进「插件 → dsh-ai-debate → 组件行」，再切换标签页，
用 `Page.captureScreenshot` 原样抓取。没有任何一张是设计稿、模拟图或手工拼的。

只放了两个测试值（Cookie 32 字符、API Key 23 字符），不是主人日常使用的
那个 profile。

## 这些截图证明了什么

1. 设置页在真实 DSH 里**能打开、能切换、有内容**——v0.1.6～v0.1.8 那几轮的
   「入口在但内容区空白」不复存在。
2. 凭据行显示的是**真实长度对应的末四位**，不是 v0.1.9/v0.1.10 的「已配置但
   长度 0」——冷启动缺陷已修。
3. 诊断面板的数字是**真值而不是占位符**（`{awaiting}` / `{input}` / `{output}`
   已修）。

## 这些截图没有证明什么

- **没有**在主人日常使用的那个 DSH profile 里重启验证过。
- **没有**点过「保存」「清除凭据」按钮走完整个浏览器写路径（写路径是用
  HTTP 请求验证的，见 CHANGELOG）。
- **没有**验证过贴吧真实帖子的完整操作流程——本机对贴吧的访问仍被 403 拦。
