# v0.3.0 首次使用指南（给没看过代码的人）

> 目标：从一台装好 DSH Desktop 的机器出发，不打开命令行，完成
> **配模型 → 粘讨论 → 生成 → 改 → 批准 → 复制**。
>
> 全程不需要微博 CLI、不需要贴吧 Cookie、不需要 OAuth。手动导入是默认入口。

---

## 准备

- DSH Desktop 已安装并能启动。
- 有一个可用的模型：宿主自带的，或一个 OpenAI 兼容接口（地址 + 模型名 + API Key）。

---

## 第 1 步：确认插件在

打开 DSH 的插件列表，应能看到「AI 代吵架」。

- 看不到：确认安装命令执行的是 `dsh plugin --profile <你的> add ...`，并重启 DSH。
- 能看到但打不开：看「诊断与状态」页的加载错误，按提示处理。

---

## 第 2 步：配模型

进入插件 → **设置 → AI 模型**。

1. 先点 **「检查宿主模型」**。如果列出模型，直接选一个，跳到第 3 步。
2. 如果宿主没有模型（提示「宿主没有提供模型服务」），选 **「自己配置的模型接口」**：
   - **地址**：形如 `https://api.example.com/v1`（以服务商文档为准）；
   - **模型名**：接口声明的 model id；
   - **API Key**：只存本机凭据库，不进配置、不进日志、不进模型上下文。
3. 点 **「测试模型连接」**。成功时会显示协议、耗时与 token 数。

**看到这些提示时怎么办：**

| 提示 | 含义 | 下一步 |
| --- | --- | --- |
| 模型配置不完整 | 地址 / 模型名 / Key 缺一项 | 补全后重新测试 |
| 认证失败 | Key 错或过期 | 换 Key |
| 协议错误 | 地址不是 OpenAI 兼容接口 | 核对 Base URL |
| 超时 | 网络或服务端慢 | 重试；仍失败则换地址 |
| 额度不足或限流 | 服务端拒绝 | 换模型或稍后再试 |
| 输出不符合契约 | 模型没按 JSON 回复 | 换模型；这是模型问题，不是你的操作问题 |

---

## 第 3 步：粘一段讨论

进入插件主页面。第一次会看到三步清单：**配模型 → 粘讨论 → 预览 + 分析 + 生成**。

1. 把一段讨论粘进输入框（支持「楼主：…」「回复：…」这类常见格式）。
2. 点 **「预览解析结果」**。这一步只做本地解析，不联网、不调模型。
3. 确认「主人 / 对手 / 楼层数」读对了，再点 **「确认导入并分析」**。

如果解析结果不对：用输入框上方的格式说明调整，或在导入后使用「修正」——修正会重跑分析，
已有候选会被作废（因为它们是对着改之前的讨论写的）。

---

## 第 4 步：选回复对象

分析完成后，评论列表会列出这次读到的发言。

- **选一条**作为要回复的对象。选不同的人会让之前的批准失效——这是有意的。
- 页面会显示「主人是谁、对手是谁、选中的是哪条」。
- 如果提示「尚未确认争论对象」，先在列表里选一条，再生成。

---

## 第 5 步：选策略与人格

- **人格**：四种，只决定说话的样子（直给、克制、犀利等）。
- **策略**：八种，决定怎么打（追问依据、指出矛盾、给反例……）。
  - 自动：系统只从材料满足门槛的策略里挑，并记录依据。
  - 手工：选了但材料不够时，会**报错并说清缺什么**，不会偷偷换一个。

两者独立：同一种人格可以用不同策略，同一种策略可以换人格。

---

## 第 6 步：生成

点 **「生成候选回复」**。结果有五种：

| 结果 | 页面说法 | 你该做什么 |
| --- | --- | --- |
| 已生成候选 | 有正文 | 继续第 7 步 |
| 材料不足，模型要求补充 | 说明缺什么 | 按提示补材料，或换一条目标 |
| 材料够，但模型拒绝回应 | 标红 | 换模型 / 换策略重试 |
| 生成了，但未通过检查 | 标红，列出原因 | 看原因；数字类问题要能追回原文 |
| 技术故障，没有生成结果 | 标红 | 重试；持续失败看诊断页 |

**材料不足时不会产生空白候选**——这是有意的。

---

## 第 7 步：改、重新评估、批准

1. 在候选区选中一条，必要时编辑正文。
2. 编辑后必须 **重新评估**：页面会重算安全判定与正文哈希，并**撤销旧批准**。
3. 确认无误后点 **「批准这条候选」**。
   - 批准绑定：正文、候选版本、目标、发表账号。
   - 其中任何一项变了，批准失效，需要重新批准。
4. 批准后「复制回复」才可用。

---

## 第 8 步：复制

点 **「复制回复」**，粘贴到你要发的地方。

- 插件**不会**替你发表。贴吧/微博的真实发表在本版禁用。
- 复制的是已批准的那条正文；未批准时按钮不可用。

---

## 第 9 步：下次打开

会话保存在独立的数据目录里（设置页会显示路径）。

- 刷新或重启 DSH 后，会话与候选仍在。
- 换一个 DSH profile 会看到另一个数据目录——历史没有丢，只是这个 profile 不看那里。

---

## 遇到问题先看哪里

1. **诊断与状态**：模型来源、平台能力、数据目录、token 用量。
2. **错误提示的「下一步」**：12 类错误都写了具体动作，不是「调用失败」。
3. **备份、升级与回滚**：见 `docs/v0.3.0-data-backup-and-rollback.md` ——
   升级前复制一份数据目录，是这三分钟里最值钱的动作。
4. 仍然不行：记录「哪一步、看到什么提示、模型来源」，再反馈。不要贴 API Key 或 Cookie。

---

## 这份指南没有承诺的事

- 不承诺真实平台可用；发表是禁用的。
- 不承诺模型一定给出好回复；它只保证「没有证据时不硬编」。
- 不承诺跨平台字节一致的安装包。
