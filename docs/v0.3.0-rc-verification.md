### 为什么不能「先硬发一个 rc 再说」

在当前 main（`7f90d6d`）上直接打 `v0.3.0-rc.1` 标签，会发生两件事，都不是「少个参数」级别：

| 位置 | 现状 | 后果 |
| --- | --- | --- |
| `scripts/lib/ship-core.mjs` 的 `assertSemver` | 只认 `^\d+\.\d+\.\d+$` | 实测拒绝：`版本号必须形如 0.2.17，收到的是 "0.3.0-rc.1"`，`ship` 在 preflight 就停 |
| `.github/workflows/release.yml` 的 `gh release create` | 不带 `--prerelease` | 标签一推，一个**候选版会被打成 Latest 正式版**：版本号对、CI 全绿，只有「是不是 Pre-release」那一个布尔值错了 |

第二件更危险：它不会让任何步骤变红。所以「缺授权」不是流程洁癖 —— 在 #38 与 #43 合并之前，
从 main 发 rc 会产出一个**看起来像正式版**的候选版。

这两处修复分别在 #43（工具链接受 rc）与 #38（工作流带 `--prerelease`），都还没合并。
