## 三、质量对比 v0.2.36 → v0.2.37

### 3.1 可比性说明（先说清楚限制）

- **确定性通道**：80 个案例，同一份语料、同一套评分器（评分器随基线产物复制运行）。
  这部分是**可复现**的。
- **语义质量通道**：需要真实模型。两版的真实输出只有：
  - v0.2.36：1 条（默认人格，`run-9850`）

### 3.3 语义质量：定性读（不给百分比）

拿 v0.2.36 那一条与 v0.2.37 四条的**共同点与差异**：

| 维度 | v0.2.36（1 条） | v0.2.37（4 条） |
| --- | --- | --- |
| 是否要求对方给出参照 | 是（「成本涨了多少你没提」） | 是（四条都在问参照） |
| 是否给出具体数字 | 否 | 否（四条都没有编造数字 —— 这是**正确**的，原文里没有） |

## 四、论证置信度：把规则匹配与事实证明分开（§5）

### 4.1 三个字段

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `evidenceKind` | `quoted` / `inferred` | 有没有**两段可核对的原文** |
| `confidence` | `high` / `medium` / `low` | 这个判断有多可靠 |
| `weight` | 0–100 | **若成立**，它有多重要 |

规则：只有 `confidence: high` **且** `evidenceKind: quoted` 才允许渲染成断言；
其余一律渲染成「待核实」，并明确写「这一条不要写成断言」。

### 4.2 条件与时间差异会降级

- 「如果成本翻倍，这方案就没法做」 vs 「这个方案的成本不会翻倍」→ 一条带条件、一条不带
  → `confidence: medium`，理由写明「可能说的是不同前提」
- 「去年这个价格是合理的」 vs 「今年这个价格不合理」→ 时间不同 → 不给 high，
  理由写明「可能是观点改变而不是自相矛盾」

### 4.3 校验层的两条硬规则

1. 标 `high` 必须有 `otherPostId` + `otherQuote` —— 没有第二段原文，不许自称事实；
2. `inferred` 不许标 `high` —— 纯规则推断最高只能到 medium。

这两条不是风格要求：渲染层就是按这两条决定「写成断言还是写成待核实」，
一个自相矛盾的标注会直接变成一句说错的话。

### 4.4 回归测试

新增 `test/v0237-decisive-confidence.test.ts`（7 条）覆盖：条件不同、时间不同、
真矛盾、纯规则推断、第三方引用、自洽性、优先级不因降级而消失。

## 五、云模型网络边界（§6，v0.2.36 的遗留缺口）

### 5.1 这一轮与「完全离线」那一轮是两个问题

| | 完全离线（v0.2.36） | 手动导入 + 云模型（v0.2.37） |
| --- | --- | --- |
| egress 模式 | `offline` | `manual` |
| 模型 | 本机假服务（回环） | 宿主云端真实模型 |
| 要证明的 | 一个字节都没出去 | 出去的只有模型，平台读写为 0 |

所以判定脚本是两份（`verify-network-boundary.ts` / `verify-cloud-boundary.ts`），
不是给同一份加参数 —— 合成的后果是把模型流量当违规（用户会去关掉模型），
或者把平台流量当模型流量放过（边界就没意义）。

### 5.2 实测结果（`tmp/desk-cloud/run-10020`）

```
· 观测器自检通过（端口 10040）：自检连接已记录并被拒绝
· 宿主自身流量 18 条（download.deepseek.com / redirector.gvt1.com / static.deepseek.com）
· 观测到连接 19 条（含观测器自检 1 条）
· 插件拦下 6 次平台出网（<spawn:version>、<spawn:commands.list>、open.weibo.com）
· 插件放行模型请求 0 次
云模型边界：通过（平台流量 0，模型流量走明确允许的渠道）
覆盖范围：Chromium 出网（经代理，逐条记录）；插件四条出口（模型/贴吧/CLI/授权探针，
由 egress.jsonl 记录）；**宿主进程 Node 出网未观测**（不得据此声称全进程零出网）。
```

### 5.3 覆盖范围（必须写清，不许外推）

| 通道 | 是否观测 | 手段 |
| --- | --- | --- |
| Electron Renderer（Chromium 网络栈） | ✅ | `--proxy-server` 指向进程外代理，逐条落盘 |
| 插件模型出口 | ✅ | 插件内 `EgressGuard` + `egress.jsonl` |
| 插件贴吧出口 | ✅ | 同上 |
| 插件微博 CLI 子进程 | ✅ | 同上（启动即拒，进程不创建就没有流量） |
| 插件授权主机探针 | ✅ | 同上（v0.2.37 之前它是**漏掉的那一条**） |
| **宿主进程 Node 出网** | ❌ **未观测** | 见下 |

**为什么宿主 Node 侧没观测**：打开 `NODE_USE_ENV_PROXY` 后，宿主自己的模型目录查询失败，
插件拿到空的 `listModels`，报「宿主有提供方，但没有可用模型」。也就是说，把宿主的
Node 出网塞进一个只做观测的代理，**会改变宿主的行为**。所以这一层的范围如实收窄 ——
不能因为它没记录就宣称「全进程零出网」。

### 5.4 一次「假绿」，以及现在的防线

第一版脚本把 profile 指到 `tmp/desk-cloud/profiles/desktop`，而 DSH 只从
`$DSH_HOME/profiles/desktop` 加载 —— 实际跑的是 real-model 目录（`egressMode: open`），
判定却读到云目录里**上一轮遗留**的 12 条 deny，结论「完美通过」。

两层修法：

1. profile 必须指向 `$ISO/profiles/desktop`（本轮 ISO = real-model 的隔离 home）；
2. 判定只认**本轮开始时刻之后**的审计；一条不剩就判失败。

第 2 条已用未来时间戳反向验证过：把 `DSH_E2E_RUN_STARTED_AT` 设成未来，
12 条旧记录全部失效，判定立刻报「插件审计里没有本轮的记录」。

## 六、顺带修的三处（都是「脚本以为改了」）

1. **`clickByLabel` 只按相等匹配**：v0.2.37 把「4 次模型调用」写进按钮文案（这是必须的 ——
   用户点之前就该知道要花四次），于是脚本找不到按钮。改成「相等优先、其次前缀」。
2. **四人格断言数名字而非数结果**：人格选择器把四个名字都渲染出来，于是
   「四个人格都在」在只有三个成功的一轮里照样变绿。改成逐行读结果行。
3. **候选快照没跟运行绑定**：store 是共享的，下一次运行会清空，于是「上一轮四个人的
   真实输出」就没了 —— 而那是要写进报告的证据。每轮结束把候选抄进 run 目录。

## 七、尚未验证 / 已知局限

### 未验证

- **四种人格 × 两个版本的盲评矩阵**：两版的真实输出不是同一组实验（1 条 vs 4 条），
  所以「新版质量提升多少」这个问题**没有答案**。报告里不给百分比。
- **真实微博写入**：0 次（本版不开放）。真实微博读取本轮 0 次（只读命令需要 CLI 登录态，
  本轮没有执行）。
- **宿主进程 Node 出网**：未观测（原因见 §5.3）。
- **并发上限**：比较是**串行**的（`compare.ts` 一次只发一个请求），没有做并发；
  因此「并发上限」这件事在行为上等于 1，没有额外实现。

### 已知局限与退化风险

- **人格只影响口吻，不影响打法**：四份的真实输出都在做同一件事（追问基准），
  论证策略没有真正分开。这一条没有被我改好。
- **硬性失败 5 条仍在**：3 条 `argument_recognition` 零结构、1 条编造数字、1 条长上下文零结构。
  它们在这一版之前就存在，这一版**没有**修好。
- **耗时波动大**：同人格 3.5–8.3 秒，不能做稳定指标。
- **`skipped` 恒等于 `failed`**：项目规则如此（跳过不能被当通过）。这一版把「不适用」
  改成「不产生该阶段」，而不是放宽规则 —— 但这意味着任何一次真正的跳过仍然会让整轮红。
