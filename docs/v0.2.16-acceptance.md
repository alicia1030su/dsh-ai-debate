## 二、§一 P0：源码包缺锁文件与编译产物

### 缺陷与根因

v0.2.15 的白名单 `ALLOWED_DIRS` / `ALLOWED_FILES` 都没有收录 `pnpm-lock.yaml` 和 `lib/`，
而工作目录里两者都在。上一版源码包 241 条目中 `pnpm-lock.yaml` 不存在、`lib/` 条目数为 0。

守卫没抓到，是因为它检查的是「锁文件覆盖了每个依赖」，不是「锁文件在包里」。
两句话听起来像同一件事，实际差了整整一层——这正是本次补齐的检查。

### 修复

- `scripts/source-zip.mjs`：`ALLOWED_FILES` 收录 `pnpm-lock.yaml`。
- `lib/` **不**作普通目录整包放行，单列 `BUILD_OUTPUT_DIRS`，只允许
  `.js` / `.d.ts` / `.js.map` / `.d.ts.map`。整目录放行的意思是「哪天有人往里丢个
  `.env`，也会一起发出去」。
- `scripts/ci-guard.mjs` 新增 §4b：直接读 ZIP 中央目录，不信打包脚本自己报的清单。
- 删除 `client/client.cjs.broken`（145,693 字节，全仓库零引用）。

### 真实性证据

- 锁文件不是抄来的：删掉后 `pnpm install --lockfile-only` 重新生成，
  与新文件**逐字节相同**（sha256 一致），`pnpm install --frozen-lockfile` 退出码 0。
- `lib/` 从零重建：232 个产物 = 58 个源文件 × 4 种后缀，缺失 0、多余 0。

### 本轮暴露并修掉的两个真实 CI 缺陷

**缺陷一（首轮 run 41106491593，两个 Node 同挂）**
`CI 完整性：runner 真的执行了磁盘上的全部测试文件` 失败。守卫拿
`process.env.CI` 当作「归档应该已经建好」的证据，而 `ci.yml` 里测试步骤
排在「生成并扫描公开源码包」之前：CI 为真、归档未生成也是真，
于是一个正常的执行顺序被判成失败。

「我在 CI 里吗」回答不了「归档建好了吗」。改为由调用方显式声明：
守卫接受 `--require-archive`，只有生成归档之后那一步传它。

**缺陷二（次轮 run 41107177933，两个 Node 同挂）**
`确认没有把凭据提交进仓库` 失败，命中测试里的假 Cookie。根因是同一件事
有两套规则：工作流里两条内联 `grep`，仓库里另有 `scripts/audit-leaks.mjs`。
审计脚本认得 `fixture-` 前缀（它自己的文档就是这么写的），内联 grep 不认。
工作流改为直接跑 `audit-leaks.mjs`，规则只剩一份，并给 `BDUSS` / `BAIDUID`
补上 `(?!fixture-)` 否词。

### 发布产物必须只由内容决定（打标签后才发现）

拿到 GitHub 发布的产物后逐字节比对，发现两处**平台指纹**——不是功能缺陷，
但它们让「发布说明里的校验和」在本项目自己的开发机上对不上：

1. **gzip 头第 9 字节（OS）**。`pack.mjs` 早把 gzip mtime 固定为 0，却漏了 OS：
   zlib 会填编译平台（Linux `0x03`、Windows `0x0a`）。Linux runner 发布的 TGZ 是
   `ac7200c3…`，同一份源码在 Windows 上重建是 `77234900…`——**长度一致，只差 1 个字节**。
   修法：`createTgz()` 把该字节固定为 `255`（unknown）。头不进 CRC，压缩与完整性不受影响。
2. **两个文件的尾部 CR**。工作区里 `scripts/configure-stage.mjs` 与
   `test/target.test.ts` 结尾是 CRLF 而仓库里是 LF，本地源码包因此比 GitHub 上的大 5 字节。

修完后本机重建的两个产物与 GitHub 发布的**字节完全一致**（见下一节）。

发布过程中修掉一个**从来没能成功过**的缺陷：`source-zip.mjs` 把源码包写在项目上一级，
而 `upload-artifact@v4` 拒绝任何含 `..` 的路径，报
`Invalid pattern '../dsh-ai-debate-source-0.2.16.zip'`。CI 一直绿，是因为 `ci.yml`
只生成和扫描、从不上传——**上传动作只在标签上才发生**。
修法是给 `source-zip.mjs` 加 `--out <dir>`（默认仍是上一级，本地开发照旧，CI 传 `--out .`），
`ci-guard` 同步改成两处都找。
