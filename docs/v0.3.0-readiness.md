# v0.3.0 准入评估

> **这份文件的用途是让人决定「现在能不能对外说这是给普通用户的产品」**，不是给 v0.2.39 打分。
> 结论只有四档，逐项标注：**已满足 / 未满足 / 缺少真实证据 / 外部授权受阻**。
>
> 判据是「普通用户能不能自己走通」，不是「测试有没有覆盖」。一个 2405 条测试全绿的构建，
> 仍然可能让一个新用户装不上、配不好、看不懂 —— 那才是这份清单要回答的问题。
>
> 评估日期：2026-11-09。基线：v0.2.39。

---

## 零、总体结论

**没有达到 0.3.0 标准，但比 v0.2.38 更接近。**

| 档 | v0.2.38 | v0.2.39 |
| --- | --- | --- |
| 已满足 | 4 | 7 |
| 未满足 | 4 | 3 |
| 缺少真实证据 | 3 | 2 |
| 外部授权受阻 | 1 | 1 |

变化的四项：源码包可独立核验（未满足 → 已满足）、首次使用有引导（缺证据 → 已满足）、
升级安全（缺证据 → 已满足）、**新增**「敏感改动待批」（`source-zip.mjs`）。

**最短的短板仍然是证据，不是功能**：真实语义质量没有被证明提升（盲评没测出来），
真实平台读写是 0/0，陌生人试用没有做。

---

## 一、逐项

### 1. 新用户全新安装 — ✅ 已满足

**判据**：在空目录里能装上一个包，且能加载。

**证据**：v0.2.38 验收在空目录建 profile、用 DSH 自带 pnpm 装 tgz，`import('dsh-ai-debate')`
返回完整导出。v0.2.39 没有改安装方式（`package.json` 的 `dsh` 字段未动），本轮 profile
重建时重复了同一条路径（安装日志显示 `+ dsh-ai-debate 0.2.39`）。

**边界**：这是「装得上」，不是「装完之后知道下一步做什么」—— 后者见第 3 项。

---

### 2. 首次模型配置 — ✅ 已满足

**判据**：宿主有模型时能直接用；没有时能自己配，并能验证连接。

**证据**：
- 「检查宿主模型」走 `probeHostLlm`，只读 `listProviders` / `listModels`，不发补全（不花额度）。
- 「测试模型连接」走 `testModel`，返回协议、耗时、token，这几个数写在页面上。
- 没有宿主模型时的提示从「调用失败」改成 `guide.ts` 的 `no_host_model`：去哪儿改、
  填什么、怎么验证，三步。

**边界**：`no_host_model` 与 `host_model_unavailable` 的区分依赖宿主返回的形状；在只提供
`stream()`、不提供 `listModels()` 的宿主上，两者会被合并成后者。这条没有穷举过。

---

### 3. 首次讨论导入与生成 — ✅ 已满足（自动驱动）

**判据**：粘一段讨论，能解析、能选目标、能生成、能确认、能复制。

**证据**：
- 离线导入面板加了三步清单（配模型 → 粘讨论 → 预览+分析+生成）。
- 导入格式说明写在输入框上方，并有一个可直接用的示例占位符。
- 生成结果五态里，`needs_more_context` 会明确告诉用户「缺什么、去哪儿补」。
- v0.2.38 的真实 Desktop 验收跑通了全流程（51 阶段）；v0.2.39 改的是结果分类与提示文案，
  没有改这条链路的调用方式（`e2e-manual-import.ts` 未改动，仍全过）。

**边界**：**这是脚本驱动的，不是陌生人走的。** 见第 12 项。

---

### 4. 微博无授权时的降级体验 — ✅ 已满足

**判据**：没有微博登录时，离线草稿仍然可用，且页面说清楚为什么。

**证据**：`sourceLine` 显示「来源：人工导入 · 未经平台核验」，预览阶段提示「插件没有向平台
核对过其中任何一条」。离线链路不读平台、不写平台。

**边界**：真实微博读取本轮 **0 次**。降级体验是「不依赖微博也能用」，不是「微博能用」。

---

### 5. 从 v0.2.37 升级后的配置兼容 — ✅ 已满足

**证据**：`test/v0239-config-compat.test.ts` 用 v0.2.37 的真实键名与值形状逐条断言：
人格、模型、安全、上下文、绑定全部生效；v0.2.38 的 `defaultStrategy` 可读；未知键被忽略；
值形状错了落回默认值；空配置每个字段都有默认值（没有 `undefined`）。

**边界**：覆盖的是「读取」。写回时未知顶层键会被丢掉 —— 见「已知缺口」第 7 条。

---

### 6. 会话与候选数据迁移 — ✅ 已满足

**证据**：`test/v0239-upgrade-safety.test.ts`：
- v0.2.37 形状（无 `argumentStrategy`）与 v0.2.38 形状（有）都能读；
- 旧 `approved: true` 读出来仍在；
- 新写入的候选 `approved: false`，**不继承旧批准**；
- store `version: 2` 拒绝启动并说明「备份后手动处理」。

**边界**：**store schema 没有升级到 v2**。当前没有真实的格式变更需求；为了版本号好看而
迁一次，只会给用户多一个失败面。

---

### 7. 异常退出后恢复 — ✅ 已满足

**证据**（全部在临时目录，不在正式用户目录）：
- 截断 `state.json` → 拒绝启动，**原文件原样保留**（不覆盖成空状态）；
- 残留 `state.json.tmp` → 正常启动，会话可读；
- 备份恢复 → 换回好文件后正常读取。

**边界**：没有做「进程在写入过程中被 SIGKILL」的精确时序注入。现有证据是「文件被截断」
这一类结果，不是「在那个瞬间被杀」。

---

### 8. 卸载与回滚不影响用户数据 — ⚠️ 未满足

**现有证据**：store 目录独立于插件目录，删掉 `node_modules/dsh-ai-debate` 不影响它。

**为什么仍是「未满足」**：
- 没有做过「v0.2.39 写 → v0.2.37 读」的完整往返测试。
- 卸载流程没有任何文档或脚本化验证。

---

### 9. 安全及网络审计范围 — ⚠️ 未满足

- 插件出口：可强制拦截（`EgressGuard` 在插件侧执行），有测试与审计日志。
- 宿主进程 Node 侧：**只能观测，不能拦截**。打开 `NODE_USE_ENV_PROXY` 会让宿主自己的模型
  目录查询失败（插件拿到空 `listModels`），所以这条路径没有被完全覆盖。

**为什么仍是「未满足」**：这是能力缺口，不是文档缺口。要变成「已满足」，需要一种不破坏
宿主模型服务的观测/拦截机制 —— 本轮没有找到。

---

### 10. 公开文档与真实功能一致 — ✅ 已满足

- README 明确当前核心能力是「讨论读取或导入 → 分析 → 生成候选 → 人工确认 → 复制」。
- 「未经真实验收的平台发表能力不得宣传为已验证」写进了 README 与 SECURITY。
- CHANGELOG 的 v0.2.39 段落只列实际改动，没有「质量提升 X%」。

**边界**：文档一致是「不撒谎」，不是「用户能看懂」。后者见第 13 项。

---

### 11. 发布包来源与可复现性 — ✅ 已满足（同平台）

**证据**：
- `source-zip.mjs` 全部字节来自 `git cat-file --batch`。
- 实测：同一提交，LF 工作树与「791 个文件被改成 CRLF」的工作树，产物 SHA256 完全相同。
- `verify-source-archive.mjs` 独立核验：归档里每个文件都等于 `git cat-file` 的字节。
- fixture 冲突已修：两个刻意入库的假微博 CLI 进包，其余 `node_modules` 仍被排除。

**边界**：**同平台同提交 → 同字节成立**；**跨平台（Linux runner vs Windows）未验证**。
不声称全平台一致。

---

### 12. 真实模型质量有可信结论 — ⚠️ 缺少真实证据

**做了什么**：三版各 20 次真实调用，同模型/人格/参数；输出随机打乱（固定种子）、隐藏版本；
两个自动评审来源（规则 / 结构），明确标注**不是人工、不是模型评审**。

**结论**：**没有测出「新版更好」。** 命中具体要素 2.75 → 2.00 → 1.85，逐版下降，而这个
指标奖励复述原文。唯一稳定达标的是「不可追溯数字 = 0」（三版都是 0）。

**为什么是「缺少真实证据」**：盲评做了，但它答不了「论证是否切中要害」—— 那需要人读。

---

### 13. 外部陌生人试用 — ⚠️ 缺少真实证据

**做了什么**：三步清单、十二类错误的下一步、数据目录说明。
**没做什么**：让任何外部测试者走一遍。
**已准备**：`docs/v0.2.39-tester-guide.md`（可直接发给测试者）。

**为什么不能写成「已满足」**：自动化流程通过 ≠ 陌生人能上手。

---

### 14. 敏感改动已完成必要审核 — ⛔ 外部授权受阻

**现状**：v0.2.39 改动了 `scripts/source-zip.mjs`（属 `pack-rules`）。这是 P0-3 的要求
（「从根本上修复，而不是仅依赖打包前发现漂移」）。

**处置**：PR 已推送、CI 会跑，但**不启用自动合并**，停在维护者审核。这是守卫的设计意图，
不应绕过。发布也因此停在 PR。

## 二、v0.3.0 Beta 准入条件逐条

| # | 条件 | 状态 |
| --- | --- | --- |
| 1 | 固定案例真实模型盲评已完成，并有可信结论 | ⚠️ 盲评完成，结论是「无提升」；语义维度仍缺人工 |
| 2 | 零重大事实编造、错误引用、错误目标缺陷 | ⚠️ 「不可追溯数字 = 0」三版成立；引用与目标只在确定性通道验证过 |
| 3 | 全新用户安装与首次使用有实际证据 | ⚠️ 自动流程通过；陌生人试用未做 |
| 4 | 旧配置与用户数据升级安全 | ✅ |
| 5 | 源码包及安装包内容可独立核验 | ✅（同平台；跨平台未验证） |
| 6 | Desktop 必需 E2E 全部通过 | ✅ |
| 7 | 模型、平台、网络权限边界如实公开 | ⚠️ 文档如实；宿主 Node 出口仍无拦截能力 |
| 8 | 没有未经批准的敏感变更 | ⛔ `source-zip.mjs` 待批 |
| 9 | 重要错误有可执行恢复指引 | ✅ |
| 10 | 外部真实用户试用已完成或明确阻断 RC 发布 | ⚠️ 未完成 |

**结论：不能进入 v0.3.0-rc.1。** 阻断项是 8（敏感改动待批）与 10（陌生人试用未做）。

## 三、已知缺口（按影响排序）

1. **语义质量没有可信结论。** 需要一个「读过这 60 条并给分」的人，或者一个与生成不同的
   模型做评审（并明确标注它是模型）。两者都还没做。
2. **真实平台读写 0 / 0。** 核心能力未验证。对外只能说「离线草稿工具」。
3. **陌生人试用未做。** 三步清单是不是真的够用，只有试过才知道。
4. **宿主 Node 出网只能观测。** 需要一个不破坏宿主模型服务的方案。
5. **跨平台字节复现未验证。** Linux runner 上的对照没做。
6. **卸载与回滚未做完整往返。** v0.2.39 写 → v0.2.37 读没有测。
7. **未知顶层键在写回时被丢弃。** 对当前版本无害（没有读者），但跨版本保留字段需要显式
   加进 `validateStore` 的重建清单 + 一次迁移测试。记录在此，不美化。

---

## 四、如果只能做三件事

1. **找人读 30 条输出并打分**（不需要 60 条，也不需要多人）。这一步能把「质量」从
   「不知道」变成「有个数」。
2. **让一个没看过代码的人装一次、用一次**，只给 `docs/v0.2.39-tester-guide.md`。
   记录他在哪一步停下 —— 那一步就是最该修的地方。
3. **真实微博读取跑通一次**（只读，最少必要）。这一步能决定「平台可用」是能力还是承诺。

这三件都不需要写代码。
