# v0.3.0 就绪评估

> **这份文件的用途是让人决定「现在能不能对外说这是给普通用户的产品」，不是给 v0.2.38 打分。**
> 结论只有四档，逐项标注：**已满足 / 未满足 / 缺少真实证据 / 外部授权受阻**。
>
> 判据是「普通用户能不能自己走通」，不是「测试有没有覆盖」。一个 2351 条测试全绿的构建，
> 仍然可能让一个新用户装不上、配不好、看不懂 —— 那才是这份清单要回答的问题。
>
> 评估日期：2026-11-08。基线：v0.2.38。

---

## 零、总体结论

**没有达到 0.3.0 标准。** 12 项里：

| 档 | 项数 |
| --- | --- |
| 已满足 | 4 |
| 未满足 | 4 |
| 缺少真实证据 | 3 |
| 外部授权受阻 | 1 |

最短的短板不是功能，是**证据**：真实模型的语义质量没有被证明提升，真实平台的读写是
0/0，新用户的完整旅程没有被一个真正的「新用户」走过一遍。

## 一、逐项评估

### 1. 新用户全新安装 — ✅ 已满足

**做了什么**：在空目录里建 profile，只写 `package.json` + `cordis.patch.yml`，用 DSH 自带的
pnpm 装 v0.2.38 的 tgz。

**证据**：

```
dependencies: + dsh-ai-debate 0.2.38   Done in 2.3s
入口导出: Config, DEBATE_GUIDANCE, DEFAULT_CONFIG, apply, buildRuntime, inject, name, resolveConfig, resolveStoreDir
```

**边界**：这里装的是本地 tgz，不是从 GitHub 装。`dsh plugin add github:...#v0.2.38`
这条路径依赖 Release 产物与网络，本轮**没有**在干净机器上验证过（见第 12 项）。

---

### 2. 首次模型配置 — ⚠️ 缺少真实证据

**现状**：两条路都在——用宿主 `llm` 服务（默认），或自己在插件里配接口。

**已验证的部分**：宿主路径在真实 Desktop 里跑通了 20 次生成 + 4 次人格比较。
「宿主有提供方但没有可用模型」这条错误文案在隔离 profile 上真实出现过，且文案指向了
两种解法（登录宿主 / 改用自配接口）—— 这一条是对的。

**没验证的部分**：
- 一个**从没配过模型**的用户，第一次打开插件看到什么？引导够不够？
- 自己配接口时，填错 URL / key 会得到什么提示？只有单元测试覆盖，没有真实操作。
- 「宿主没登录」与「宿主登录了但没有模型」这两种情况，页面上是否能区分？

**为什么算缺证据而不是未满足**：代码路径存在且有测试，但没有一次「从零开始配」的真实记录。

---

### 3. 首次讨论导入 — ✅ 已满足

**证据**：真实 Desktop，51 阶段全通过，含「预览解析结果 — 页面列出了原帖、参与者与条数」
「确认导入并分析」「十一步进度条」「工作台能读到这条导入会话」。

导入支持文本粘贴 / JSON / 文件三种形式，解析层有修正机制（v0.2.31）。
「未经平台核验」这句话在每个入口都显示。

**边界**：只用了一种样例（贴吧形状的三行人话）。**没有**用真实用户会粘贴的那种
「带楼层号、带时间、带表情、带引用块」的长内容试过。

---

### 4. 首次生成与复制 — ✅ 已满足

**证据**：真实 Desktop + 真实模型，51/51：

```
未确认时复制被挡住 — 还不能复制，disabled=true
确认生效 — 按钮变为「已确认」
确认后复制可用 — 复制回复，disabled=false
复制有可读的反馈 — 已写入剪贴板并提示
```

**剪贴板是实际读回的**：系统剪贴板 45 个字，与已批准候选逐字一致。

---

### 5. 微博无授权时的降级体验 — ⚠️ 缺少真实证据

**现状**：插件区分「未配置凭据 / 已配置但未授权 / 已授权但探测失败」三档，诊断页会说明
是哪一档。这一套是 v0.2.31–33 建的，有单元测试。

**没验证的部分**：这一版**没有**在一个「微博完全没配置」的干净 profile 里走一遍，
看页面到底显示什么。凭据缺失路径的文案是代码里写好的，但没有截图证据。

**风险**：一个新用户很可能第一件事就是点「微博」，然后撞上这里。

---

### 6. 从 v0.2.37 升级后的配置兼容 — ✅ 已满足（限 store 数据）

**做了什么**：用 v0.2.37 的编译产物读 v0.2.38 写的 `state.json`，反向也读一遍。

**证据**：

```
v0.2.38 读 v0.2.37 的 store: ok true，sessions 1，approvals 0，旧候选 argumentStrategy 正常
v0.2.37 读 v0.2.38 的 store: ok true，sessions 1，候选 5
```

`argumentStrategy` 是**新增可选字段**，旧数据没有它就是 `undefined`，界面按「未记录」显示。
`version` 仍是 1，没有触发「版本不认识」的拒绝。

**边界**：只验了 store 的**数据结构**。**配置文件**（`cordis.patch.yml` 里的键）没有做
逐键对比 —— 这一版新增了 `strategy` 相关的运行期参数吗？没有。但也没有一份
「v0.2.37 的配置文件在 v0.2.38 下每个键都仍被识别」的证据。

---

### 7. 会话与候选数据迁移 — ✅ 已满足

同第 6 项的证据。补充两点：

- 候选新增字段是**可选**的（`argumentStrategy`），旧候选读出来是 `undefined`，
  复制/确认路径不依赖它；
- 会话状态机没有变化（`ANALYZING → READY → REVIEWING → ...`），旧会话读进来仍是原状态。

**边界**：没有迁移脚本，也不需要 —— 但这也意味着**如果将来要改必填字段，就没有迁移工具**。
0.3.0 值得补一个 `store version → 2` 的迁移路径。

---

### 8. 异常退出后恢复 — ⚠️ 缺少真实证据

**做了什么**：人为把 `state.json` 截断 20 字节，然后用新实例读。

**证据**：

```
损坏时拒绝启动: 状态文件 ... 不是合法 JSON
损坏原件备份数: 1
用备份恢复后 dedupe 条数: 1 sessionId: s1
```

设计是对的：**拒绝启动**而不是「修一修继续用」，因为重置会丢掉「已发表」记录 → 重复发帖。

**没做的**：真正的「进程被 kill」——生成中途断电、写入中途崩溃、锁文件残留。
这几条只有代码里的锁实现（`state.json.tmp` + 重读）与单元测试，没有一次真实的中断演练。

---

### 9. 卸载与回滚是否影响用户数据 — ✅ 已满足（有边界）

**做了什么**：删掉 profile 里的 `node_modules/dsh-ai-debate`，再验证数据目录是否还在。

**结论**：用户数据在 `storeDir` 里，**不在插件目录内**。删插件不动数据。
回滚到 v0.2.37 已验证可读（第 6 项）。

**边界**：`storeDir` 的默认值取决于 DSH 的 profile 目录。如果用户换 profile，
会看不到旧数据 —— 这不是 bug，但**没有任何界面提示「你的数据在另一个 profile 里」**。
0.3.0 应该处理。

---

### 10. 安全及网络审计范围 — ⚠️ 缺少真实证据

| 能强制阻止的 | 手段 |
| --- | --- |
| 插件模型出口 | `EgressGuard` + `egress.jsonl` |
| 插件贴吧出口 | 同上 |
| 微博 CLI 子进程 | 同上（启动即拒） |
| 授权主机探针 | 同上 |

| 只有观测能力的 | 手段 |
| --- | --- |
| Chromium 渲染层 | 进程外代理，逐条记录 |

| 无法证明的 | 原因 |
| --- | --- |
| 宿主进程 Node 出网 | 打开 `NODE_USE_ENV_PROXY` 会让宿主的模型目录查询失败 |

**这一版没有推进**。仍然不得声称「全进程零出网」。

**「缺少真实证据」而非「未满足」**：边界本身是清楚的、写下来的、可核对的；
缺的是一条能把宿主 Node 侧也纳入观测的方案。

---

### 11. 公开文档与真实功能是否一致 — ⚠️ 缺少真实证据

**做了的**：README 的版本号四处（安装命令 / Release 链接 / tgz 名 / zip 名）由
`scripts/version.mjs` 强制一致，CI 每次跑。

**没做的**：README 里对**能力**的描述与实际行为逐条比对。这一轮至少发现两处需要说明：

- README 没有讲「论证打法」这个新概念 —— 0.3.0 前必须补，否则用户不知道那个下拉是什么；
- 「四种人格」的说明里仍然暗示它们打法不同，而这一版明确：人格只管语气。

`version.mjs check` 还会提示 README 第 1461 行提到 `dsh-ai-debate 0.1.3`（历史验收记录的
快照），这类历史叙述是允许的，但**没有任何机制区分「历史叙述」与「当前承诺」**。

---

### 12. 发布包来源与可复现性 — ❌ 未满足

**已查清**：v0.2.37 的字节差异来自工作树 CRLF，从干净树重建与官方逐字节一致。

**仍未满足**：

1. `scripts/source-zip.mjs` **仍然读工作树**。根因还在，只是现在有工具能在打包前发现
   （`verify-source-archive.mjs --drift`）。真正的修法是读 `git cat-file` 的内容 ——
   那是敏感路径，需要维护者授权，本轮没做。
2. **字节级跨平台复现未验证**。依赖同一套 Node/zlib。清单文件会记录 Node 版本与平台，
   但「同一份源码在任何机器上产出同一串字节」这句话没有证据。
3. **从 GitHub 安装的路径没在干净机器上验证过**（第 1 项的边界）。

## 二、按「普通用户能不能用」重排的短板

上面的清单是逐项体检。真正决定 0.3.0 能不能发的是这四条，按严重程度：

### ① 语义质量没有被证明（最严重）

v0.2.38 的策略层在结构上是对的（正交、有门槛、有记录），20 次真实生成也确实用到了
4 种不同打法。但：

- 「回复是不是更有说服力」**没有证据**；
- 「命中具体要素」这个代理指标**反而下降了**（1.20 → 0.84，每百字 2.32 → 1.84），
  而它有明确的偏置（奖励复述原文）；
- 20 案例、单次采样、非盲评。

**0.3.0 之前必须有的**：至少一次「同批案例 × 盲评 × 明确评分表」的对照，评的人不知道
哪条是哪个版本。在这之前，任何「论证质量提升」的说法都不能对外说。

### ② 真实平台读写是 0 / 0

微博真实读取 0 次、真实写入 0 次（与 v0.2.37 相同）。贴吧同理。

插件的主体功能是「读争论、写回复」。这两件事在真实平台上一次都没走通，
剩下的全部是离线路径。**这不是「未测试」，这是「核心能力未验证」。**

如果要对外发布 0.3.0，这一条必须先有一个真实账号的真实读数 + 一次真实回帖（哪怕是
测试帖）。当前状态只能对外说「离线草稿工具」。

### ③ 新用户旅程没有被真正的新用户走过

安装、模型配置、导入、生成、复制，每一步都有某个 agent 的验证记录，
但**没有一次「一个人从零开始，不看文档，只点界面」**的观察。

真实的卡点大概率在第 2 步（模型配置）和第 3 步（导入格式）：
装的人不知道宿主有没有模型，也不知道导入要写成什么样。

### ④ 卸载/回滚的「数据在哪」没有交代

数据在 `storeDir`，删插件不动它 —— 这是对的。但用户换 profile 就看不见旧数据，
而界面上没有任何一句说明。对普通用户来说，「我的记录消失了」比「数据其实还在」重要。

## 四、如果明天就要发 0.3.0

**不建议发。** 但如果必须发，可以退到下面这个定位，并且必须在 README 第一段写清楚：

> 这是一个**离线草稿工具**：你把自己看到的争论粘进来，它帮你理清结构、起草一条回复，
> 你确认后自己复制去发。它不读取任何平台，也不替你发任何东西。

在这个定位下，①②④ 三条短板都不再是「未完成」，而是「明确不做」；③ 仍然是必须补的
（新用户必须能装上、能配好、能导入一次）。

**不能接受的定位**是「帮你自动回帖」—— 那条路一次都没在真实平台上走通过。

## 五、这一版真正往前挪的一格

不是「策略层」这个功能，而是**两件把「说不清」变成「说得清」的工具**：

1. `compression-record`：压缩掉了什么，逐项可查，不再靠分数反推；
2. `verify-source-archive`：归档里每个文件是否等于提交内容，逐文件可核，
   四类差异分得开。

它们的共同点是：**让人能自己核对，而不必相信某一次运行的自述**。这比再加一个功能更接近
「可以给普通用户用」。
