## 一、失败复现（先复现，再修）

任务书要求六个缺陷「先建立失败复现，再修改代码」。以下每条都先写成会失败的测试，
确认它确实失败，改完再确认转绿。

### 1. 两个 store 共享 state.json 导致丢失更新

`test/v027-multi-store-loss.test.ts`。修复前的真实输出：

```
✖ 两个 store 交错写同一文件，后写的覆盖先写的
    磁盘上的安全事件: ["evt-from-b"]          ← A 的记录消失了
✖ 两个 store 交错写去重台账，confirmed 记录被覆盖
    AssertionError: A 的 confirmed 记录必须还在
✖ 批准记录被另一个实例的写入冲掉
    磁盘上的批准记录: []                      ← 批准记录整个消失
ℹ pass 0   ℹ fail 3
```

成因（源码级）：`buildRuntime()` 里 `new DebateStore(...)`，而 `currentRuntime()`
在配置/凭据变化时重新调用 `buildRuntime()`。同进程内因此出现两个指向同一文件的
store，各持私有副本，后写者覆盖先写者。

### 2. 批准请求没有候选快照

复现路径：`client/client.cjs` 的 `approve()` 只发 `{sessionId, candidateId}`；
`index.ts` 的 `createApprovalForSettings` 只读这两个字段，把记录绑到**请求时刻**的
存储内容。旧页面 → 新候选的组合会产出一份内部自洽、下游无法察觉的记录。

### 3. `checkReassessment` 接受缺失指纹

`src/security/approve-guard.ts:100`：`if (requested === undefined) return { ok: true }`。
不说明看到什么，反而比说明更容易通过。

### 4. 切到发表授权标签不刷新

`client/client.cjs` 的 `setTab(tab)` 只有 `this.tab = tab; this.publish()`。

### 5. 微博只有 manifest

`src/platforms/weibo/` 目录此前不存在。

### 6. 跨重启恢复 / 适配器重建无测试

`grep` 全部 `test/*.ts`：没有任何测试同时断言「新 store 实例读到原 platform」或
「配置变化后 adapter 实例不同」。v0.2.6 的 CHANGELOG 自己记了这两项是实测而非测试。

## 二、修复内容

### 状态一致性（三层）

| 层 | 做法 |
| --- | --- |
| 进程内 | `buildRuntime` 新增 `store` 注入点；`apply()` 用 `storeFor(config)` 复用一个实例，重建 runtime 时递同一个 store |
| 跨进程 | `mutate` 在**锁内**重读盘 → 合并 → 写。锁用 `open(path,'wx')` 原子创建，超时抛错而非无锁写入 |
| 读一致性 | `refreshFromDisk()` 在 `dirty` 为真时直接返回；发布路径决策前先刷新 |

锁的细节：锁文件记 `{pid, at}`；持有者已死（`process.kill(pid,0)` 报 ESRCH）且超
30 秒才抢占；抢占用 `rename` 而不是 `unlink`，两个抢锁者不会互删。

**遵守的约束**：没有用定时读文件替代并发保护；没有在锁失败时静默忽略写入
（拿不到锁 → `write_failed` + 脏标记 → 发布被拒）；没有在写失败时重新初始化空库。

### 批准快照

- `PendingApprovalView` 新增 `expected`（8 字段）与 `assessmentFingerprint`
- 新增纯函数 `readExpectation` / `checkExpectation`（`src/security/approve-guard.ts`），
  路由与测试共用同一份实现，不是两份
- 客户端原样回传，页面**不计算**任何一项
- 无快照 → `400 snapshot_required`；缺字段 → `400 snapshot_incomplete`；
  任何漂移 → `409 stale_candidate` 并指名是哪一项

### 待批准列表刷新

`setTab('approve')` 触发 `refreshApprovals()`；新增刷新按钮；四态
（`loading` / `failed` / 空 / 有）。**读取失败不渲染成空列表**。

### 微博只读

| 交付 | 说明 |
| --- | --- |
| `weibo/url.ts` | 5 种链接形状；`threadId` 一律 normalise 成 numeric mid；base62 ↔ numeric 双向 |
| `weibo/conversation.ts` | 投影到 ConversationGraph，**不造楼层号**；转发是独立节点 + `reposts` 边 |
| `weibo/provider.ts` | 注册进注册中心；能力矩阵**零 supported / 零 unverified**；读方法抛 `WeiboNotAuthorisedError` |

**未交付且不假装**：没有 OAuth 客户端、没有接口路径、没有 scope 字符串。
没有取得开放平台授权，也没有对线上接口发过任何请求。

### 顺带修掉的显示谎言

`describePlatforms` 原来对任何已注册 provider 写 `implemented: true`。微博一注册，
设置页就会画成绿色「已实现」。改为由能力矩阵推导（存在 `supported`/`unverified` 才算）。
