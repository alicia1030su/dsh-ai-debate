## 一、一个必须先说的前提：这两版的可执行代码完全相同

| 目录 | 比对结果 |
| --- | --- |
| `package/lib/` | **逐字节相同**（`diff -rq` 无输出） |
| `package/client/` | **逐字节相同** |

v0.3.0 这一轮改的是 `scripts/`（归档完整性、候选构建）、`test/`、`docs/`、版本号与说明，
没有动 `src/` 与 `client/`。所以任何生成质量上的差异**都不可能归因于代码改进**，
只能归因于模型采样。这一点决定了下面所有数字只能当作「同一实现两次采样的波动」。

写清楚这件事比给一个好看的数字重要：否则下一版会说「v0.3.0 比 v0.2.39 好，
因为不可追溯数字从 X 降到 Y」，而它们跑的是同一份代码。

同一案例上结果类型相同的：**28 / 30**。不同的是 `q06`（长楼层）与 `q17`（未说前提）：
v0.3.0 两次都判成 `needs_more_context`，v0.2.39 两次都给出了正文。

这两条的值不值得当成问题，要看正文质量才能判断，而那需要人看。**规则分数不能替代这个判断。**

### 唯一一条 `technical_failure` 两版相同

`q30`（两个口径都对）在两次运行里都在 3–4 毫秒内失败，原因是**争论简报没通过证据校验**：

```
disagreements：没有指出任何具体分歧，也没有说明为什么没有分歧
```

这不是模型慢或超时，是确定性校验在生成之前就拦住了。`src/brief.ts` 的规则是：
没有分歧可以，但必须说明为什么没有。这条案例恰好是「两边都对、口径不同」，
模型没有解释这个「没有分歧」的成因，于是被拦。

这条是**真发现**：它说明该规则在「双方其实不冲突」的案例上偏严——模型得先学会
说「这两句不是同一件事」才能通过，而不是直接给出「两个口径都成立」的回复。
本轮不改规则：改判定阈值需要重新论证「什么算解释过了」，而这轮没有人工评审证据支撑。

**不能当成改进或退步**；要判断得靠人工评分，而那是 0 人。

## 六、这一节能说什么

1. 30 条案例在真实 Desktop + 真实宿主模型上**跑得通**，两版各 30 次调用，0 次崩溃；
2. 五个结果类型里出现了三种（`valid_draft` / `needs_more_context` / `technical_failure`），
   说明五态分类在真实样本上真的会分流，不是纸面字段；
3. 两版都**没有**编造不可追溯的数字；
4. `q30` 暴露了简报校验在「双方不冲突」案例上偏严，是一条可复现的真实缺陷；
5. `q06` / `q17` 的结果类型在两版间不一致，但两版代码相同——说明这是采样波动，
   样本量（各 1 次）不足以判断方向。

## 七、这一节不能说什么

- **不能说 v0.3.0 比 v0.2.39 质量更好或更差**：可执行代码逐字节相同，差异是采样；
- **不能说语义质量达标**：没有人工评分，规则指标只覆盖「空不空、有没有针对性、数字可不可追溯」；
- **不能说出结论的稳定性**：每条案例只跑 1 次。要谈方差，每条至少 3 次，本轮预算不允许。
