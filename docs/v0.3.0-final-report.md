以后再把判定拆到新文件而忘记登记，CI 会直接变红。

负向测试：改这三个文件（包括只改注释）都会命中敏感闸门，不会进入普通自动合并。

### #32 授权必须绑定最终代码

**已修（PR #42）**。恢复合并态时不再看 `pr.state`，而是同时要求：

1. 状态文件里有审核锚点（head / tree / 每个改动路径的 blob）；
2. GitHub 上有维护者的 `ship-approval: v1` review，作者是仓库 owner；
3. review 的 `commit_id` = 评论里的 head = 审核锚点；
4. `scope` 覆盖全部敏感路径；
5. 授权时间早于合并时间；
6. PR 最终 head 仍等于锚点（新提交 → 旧授权失效）；
7. 合并内容逐 blob 等于审核内容（squash 新提交允许，不比 SHA）；
8. 打标签前再核对 main 上的内容，且合并提交必须是 main 的祖先。

行为回归（真实 Git 仓库，30 条）：

- 审核 A → 推 B → 合并 B → **拒绝**；
- 授权 A → 合并 A → 允许（squash 生成新提交也允许）；
- 基线前进但审核路径内容不变 → 允许；
- 授权范围漏路径、授权属于别的 PR、授权晚于合并、合并多带敏感路径 → 全部拒绝。

流水线里没有创建 review 的代码，测试里有一条断言钉住这一点。
